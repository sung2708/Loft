# Room whiteboard

Open **Bảng vẽ / Whiteboard** from the call dock. The board replaces the local stage; calls, screen tracks and music stay mounted. Close the board with the same button.

- `tldraw` 5.6.0 is embedded locally. No public demo sync rooms are used.
- Every admitted room participant, including guests, may draw, edit and erase. The server derives cursor names from the authenticated room connection, never from client-supplied names.
- Drawing, geometric shapes, text, sticky notes, arrows, lines, highlights, frames and groups are supported. File uploads, embedded web pages, image/video assets, page switching and document import are disabled.
- PostgreSQL owns the document (`room_whiteboards`). Apply migration `000013_room_whiteboards.up.sql` before deployment. RLS is enabled and client roles have no table access; only the Go API writes it.
- `GET /api/v1/rooms/{roomID}/whiteboard` returns the full versioned snapshot. Conditional reads send `If-None-Match: "board-<version>"`; unchanged boards return 304 using a version-only query, without loading the document. `PATCH` takes `{version, put, remove}`. A row transaction and version compare reject stale writers with 409. The client fetches a new snapshot and overlays its pending record edits before retrying. Other participants' distinct records are preserved. Concurrent edits of the **same record** resolve by the last successfully submitted record; this is not character-level collaborative text editing.
- `board.changed` notifies room sockets after commit; clients fetch the snapshot. A two-second bounded polling fallback repairs dropped notifications. Normal drawing batches are delayed 150–200ms, one HTTP request is in flight per board, and retries back off on transient errors. Permanent 400/401/403/413 responses pause saving and keep local edits until they are changed or explicitly discarded. There is no historical replay buffer.
- `board.cursor` publishes typed page coordinates, drawing state and visibility. Go adds the verified connection ID and display name. Clients expire stale cursors and hide disconnected participants. Cursor updates are throttled; media packets never enter this channel.
- Records are checked against the pinned SDK structure and supported property values before persistence. Edited parent chains are checked against the merged snapshot and cycles are rejected; clients quarantine untouched legacy cycles and their descendants without blocking unrelated new edits. Rich text node/mark types use exact membership checks. Clients also isolate malformed legacy records so they cannot block the rest of the board. Shared SDK fixtures cover server/client compatibility.
- Limits: 1,500 document records, 2MiB document payload, 64KiB per record, 200 records per patch, 256KiB request body. Uploads are excluded. WebSocket enqueues use existing room backpressure. Database work and event publishing occur outside room locks.
- `NEXT_PUBLIC_TLDRAW_LICENSE_KEY` is required for production domains under the SDK license. Development on localhost works without it. Obtain a valid license from tldraw; do not use the public demo service for private room data.

References: https://tldraw.dev/docs/collaboration and https://tldraw.dev/docs/sync

Verification includes real tldraw in two independent test browsers with an isolated authoritative transport fixture: concurrent drawing, named cursors, board toggling, and reload recovery. Backend tests cover admission, cross-room rejection, stale-version rejection and record limits; Go race tests cover the complete backend. A real PostgreSQL test covers concurrent pick capacity and atomic autoplay/selection persistence. Live multi-node Redis delivery and a production license have not been validated.
